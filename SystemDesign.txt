# JRR Transport Logistics Management System
## Enterprise System Architecture & Comprehensive Detailed Design Specification
---
## 1. Executive Summary & Architectural Philosophy
The **JRR Transport Logistics Management System** is a mission-critical, enterprise-grade logistics, telematics, and workforce management platform designed for modern multi-modal transport and freight operations. 
### Architectural Core Principles:
1. **Omnichannel Ingestion**: Seamless ingestion of commercial B2B freight requests alongside public direct-to-consumer bookings.
2. **Deterministic Dispatch & Conflict Prevention**: Real-time locking of human and vehicular assets to eliminate dual-booking, combined with open-source road network routing (OSRM) and volumetric rating engines.
3. **High-Frequency Telematics & Spatial Visibility**: Millisecond-level location tracking, live radar plotting, and proactive geofencing.
4. **Resilient Dual-Tier Authentication**: Zero single-point-of-failure authentication supporting Cloud Identity (Supabase GoTrue), local cryptographic fallback, rate-limiting, and 3-stage OTP password recovery.
5. **Automated Compliance & Financial Finalization**: Integrated Philippine statutory payroll engine (BIR TRAIN Law, SSS, PhilHealth, Pag-IBIG), sequential accounts receivable invoicing, and customer milestone webhooks.

### Security Boundary Protections:
1. **Zero Public Port Forwarding**: The Express server listens on local interface `0.0.0.0:3000`. No router NAT ports are opened. Ingress is exclusively handled via an outbound persistent QUIC connection established by `cloudflared.exe`.
2. **Electron Context Isolation**: The desktop admin application enables `contextIsolation: true` and `nodeIntegration: false`. Renderer processes communicate strictly via `preload.ts` exposed IPC bridges.
3. **Brute-Force & Credential Shield**: In-memory rate limiting locks accounts for 15 minutes after 5 failed authentication or OTP verification attempts.
4. **Client Inactivity Guard**: `auth_guard.js` monitors DOM events (`mousemove`, `keydown`, `scroll`, `touchstart`) and forces logout upon 30 minutes of idle time.

## 4. End-to-End Operational Lifecycle & Master State Machine

The master operational lifecycle spans customer demand, dispatch conflict locking, pre-trip inspection, real-time transit telematics, waypoint deliveries, proof of delivery, and financial settlement:

```mermaid
stateDiagram-v2
    [*] --> OrderIngestion: Customer Web Booking OR Dispatcher Scheduling
    
    state OrderIngestion {
        [*] --> DraftOrder
        DraftOrder --> VolumetricEstimation: Compute Dimensions & Weight
        VolumetricEstimation --> OSRMRouting: Compute Dual-Leg Geometry
        OSRMRouting --> RateCardCalculation: Apply Base Fare + Per-Km + Stop Surcharges
        RateCardCalculation --> ResourceAssignment: Select Driver & Vehicle
    }

    OrderIngestion --> AssetConflictCheck: Validate Driver & Vehicle Availability
    
    state AssetConflictCheck {
        [*] --> CheckStatus
        CheckStatus --> ConflictDetected: Driver or Vehicle != 'available'
        ConflictDetected --> ResourceAssignment: Re-select Resources
        CheckStatus --> PreTripInspection: Resources Available
    }

    state PreTripInspection {
        [*] --> VehicleChecklist
        VehicleChecklist --> SafetyLock: Critical Failure in 12-point Assessment
        SafetyLock --> [*]: Vehicle Marked 'maintenance'
        VehicleChecklist --> DispatchManifestReady: Assessment Passed
    }

    PreTripInspection --> Scheduled: Trip Inserted (status = 'scheduled')
    Scheduled --> InTransit: Driver taps 'Start Trip' in Mobile App
    
    note right of Scheduled
        Milestone Email 1 Dispatched:
        ORDER BOOKED
    end note

    state InTransit {
        [*] --> TelematicsStreaming
        TelematicsStreaming --> MilestoneApproaching: Driver within 15 mins of destination
        TelematicsStreaming --> WaypointArrival: Arrived at Intermediate Stop (trip_stops)
        WaypointArrival --> WaypointDelivery: Complete Stop e-POD
        WaypointDelivery --> TelematicsStreaming: Next Waypoint
        TelematicsStreaming --> IncidentOccurred: SOS Panic or Road Breakdown
        IncidentOccurred --> EmergencyProtocol: Admin Siren Alert Triggered
        EmergencyProtocol --> TelematicsStreaming: Resume Transit
    }

    note right of InTransit
        Milestone Email 2 Dispatched:
        OUT FOR DELIVERY (Live GPS + Driver Details)
    end note

    note right of MilestoneApproaching
        Milestone Email 3 Dispatched:
        ARRIVING SOON
    end note

    InTransit --> FinalDeliveryCheck: Reached Final Destination
    
    FinalDeliveryCheck --> Delivered: Recipient Signs Touch Canvas e-POD + Photo Upload
    FinalDeliveryCheck --> FailedDelivery: Consignee Absent / Goods Refused

    note right of Delivered
        Milestone Email 4 Dispatched:
        DELIVERED (Signatory Name + POD Proof)
    end note

    note right of FailedDelivery
        Milestone Email 5 Dispatched:
        DELIVERY ATTEMPTED (Reason Logged)
    end note

    Delivered --> SettlementAndSettling: Auto-Release Assets ('available')
    FailedDelivery --> SettlementAndSettling: Auto-Release Assets ('available')

    state SettlementAndSettling {
        [*] --> AccountsReceivable
        AccountsReceivable --> SequentialInvoicing: Generate INV-YYYY-XXXX
        SequentialInvoicing --> PaymentReceipt: Mark Paid upon Client Remittance
        [*] --> WorkforceSettlement
        WorkforceSettlement --> AttendanceHours: calcHours(check_in, check_out)
        AttendanceHours --> TRAINPayroll: Deduct SSS, PhilHealth, Pag-IBIG & Tax
        TRAINPayroll --> FinalizePaychecks: Dispatched Branded HTML Payslips
    }

    SettlementAndSettling --> [*]
```

## 5. Detailed Subsystem Specifications & Illustrations

### Subsystem 1: Identity, Dual-Store Authentication, Lockout & OTP Recovery

```mermaid
sequenceDiagram
    autonumber
    actor User as Employee / Admin
    participant UI as Login Portal (index.html)
    participant Guard as Session Guard (auth_guard.js)
    participant AuthAPI as Auth Router (/api/auth)
    participant SupaAuth as Supabase GoTrue Auth
    participant DB as Postgres (users / employees)
    participant SMTP as NodeMailer SMTP Server

    User->>UI: Input Email/Username & Password
    UI->>AuthAPI: POST /api/auth/login

    rect rgb(245, 245, 255)
        Note over AuthAPI: Check 1: Super Admin Master Bypass
        alt Credentials == admin / admin@jrr.com + admin
            AuthAPI-->>UI: HTTP 200: role = 'super_admin' (Full Bypass)
        end
    end

    rect rgb(255, 240, 240)
        Note over AuthAPI: Check 2: Brute-Force Rate Limiting
        alt Failed attempts >= 5 in loginAttempts Map
            AuthAPI-->>UI: HTTP 429: Account locked for 15 minutes
        end
    end

    AuthAPI->>SupaAuth: signInWithPassword({ email, password })

    alt Supabase Auth Succeeds
        AuthAPI->>DB: Query users (WHERE email = ?)
        alt email_verified == false
            AuthAPI-->>UI: HTTP 403: Email verification required
        else account_status != 'approved'
            AuthAPI-->>UI: HTTP 403: Account pending administrator approval
        else Account Active & Approved
            AuthAPI->>DB: Query employees (WHERE supabase_user_id = user.id)
            AuthAPI-->>UI: HTTP 200: Employee Session Payload + Access Token
        end
    else Supabase Auth Fails (Network / Legacy / Unsynced User)
        AuthAPI->>DB: Fallback Query users (WHERE email = ? AND password = ?)
        alt User Match in Database
            AuthAPI-->>UI: HTTP 200: Local Database Session
        else Invalid Credentials
            AuthAPI-->>UI: HTTP 401: Invalid credentials (Attempts remaining recorded)
        end
    end

    UI->>Guard: Save user session & lastActivity in localStorage
    Guard->>Guard: Set 30-min idle timer; reset on mousemove, keydown, click
    
    opt Idle Exceeds 30 Minutes
        Guard->>UI: Auto-terminate session & redirect to index.html
    end

    %% 3-Stage Password Recovery
    rect rgb(240, 255, 240)
        Note over User, SMTP: 3-Stage Rate-Limited Password Recovery Flow
        User->>UI: Click "Forgot Password", submit email
        UI->>AuthAPI: POST /api/auth/send-recovery-code
        AuthAPI->>DB: Verify email exists in users
        AuthAPI->>AuthAPI: Generate 6-digit cryptographic OTP (expires in 15 mins)
        AuthAPI->>SMTP: Send Branded HTML OTP Email
        AuthAPI-->>UI: HTTP 200: Code dispatched
        User->>UI: Input 6-digit OTP code
        UI->>AuthAPI: POST /api/auth/verify-recovery-code
        AuthAPI-->>UI: HTTP 200: OTP Validated
        User->>UI: Input New Password (min 8 chars)
        UI->>AuthAPI: POST /api/auth/update-password-with-code
        AuthAPI->>DB: UPDATE users SET password = ?
        AuthAPI->>SupaAuth: supabaseAdmin.auth.admin.updateUserById(id, { password })
        AuthAPI-->>UI: HTTP 200: Password reset successful
    end
```

### Subsystem 2: Omnichannel Order Inflow, Multi-Stop TMS Dispatch & Contract Dynamic Pricing

```mermaid
flowchart TD
    %% Inflow Channels
    subgraph Ingestion_Channels ["Order Ingestion Channels"]
        WebPortal["Public Customer Booking\n(transport_web_site/booking.html)"]
        DispPortal["Commercial Dispatcher Hub\n(scheduling_page.html)"]
    end

    %% Web Order Processing
    WebPortal --> WebProxy["api.php Proxy Script"]
    WebProxy --> CheckClient{Client Phone Registered?}
    CheckClient -- No --> InsertClient[(Insert clients Table:\nclient_type: 'Individual'\ncompany_name: 'Website Booking')]
    CheckClient -- Yes --> UpdateClient[(Update clients Name/Email)]
    InsertClient & UpdateClient --> CreateWebTrip[(Insert trips Table:\ntrip_number: 'TRP-WEB-timestamp'\nstatus: 'scheduled')]

    %% Dispatcher Flow
    DispPortal --> InputLocations[/Select Origin HQ, Pickup & Delivery Points/]
    InputLocations --> OSRM_DualLeg["POST /api/tracking/estimate-route\n(OSRM Engine)"]
    
    OSRM_DualLeg --> ComputeLegs["Compute Dual-Leg Coordinates:\n• Leg 1 (Dispatch): HQ -> Pickup\n• Leg 2 (Delivery): Pickup -> Dropoff\nOutput: leg1_distance_km, leg2_distance_km, duration_mins"]
    
    ComputeLegs --> VolumetricEngine["POST /api/tracking/estimate-package\nVolumetric Weight = (L * W * H) / 5000\nChargeable Weight = max(Actual, Volumetric)"]
    
    VolumetricEngine --> RateCardCheck["Query client_rate_cards Table"]
    RateCardCheck --> FreightFormula["Compute Dynamic Price:\nBase Fare + (Distance Km * Per-Km Rate) +\n(Waypoints * Stop Surcharge)\nAssert >= min_charge"]

    FreightFormula --> ResourceCheck[/Select Driver & Vehicle/]
    ResourceCheck --> ConflictValidation{Resource Conflict Check}

    ConflictValidation -- Driver Busy on Active Trip --> ErrDriver[Reject HTTP 400: Driver currently engaged]
    ConflictValidation -- Vehicle Busy on Active Trip --> ErrVehicle[Reject HTTP 400: Vehicle currently in transit]
    ConflictValidation -- Delivery Time <= Pickup Time --> ErrTime[Reject HTTP 400: Chronological timestamp error]
    
    ConflictValidation -- Validation Passed --> InsertTrip[(Insert trips Table:\ntracking_code: 'TRK-XXXXXXXX'\nstatus: 'scheduled')]

    %% Multi-Stop Logic
    InsertTrip --> CheckWaypoints{Contains Intermediate Stops?}
    CheckWaypoints -- Yes --> InsertWaypoints[(Insert trip_stops Table:\n• stop_sequence: 1..N\n• stop_type: pickup/dropoff/waypoint\n• tracking_code per stop\n• status: 'pending')]
    CheckWaypoints -- No --> LockResources

    InsertWaypoints --> LockResources
    CreateWebTrip --> LockResources

    LockResources[(UPDATE employees SET status = 'in-use'\nUPDATE vehicles SET status = 'in-use')]
    LockResources --> TriggerNotification[(Insert notifications Table:\nurgency: 'alert', title: 'New Trip Assigned')]
    LockResources --> DispatchMilestone1["notificationWebhook.ts:\nMilestone 1 Email (ORDER BOOKED)"]

    %% Deletion & Asset Recovery
    subgraph Asset_Recovery ["Trip Cancellation & Asset Auto-Release"]
        DelReq([DELETE /api/trips/:id]) --> DelDB[(Delete from trips)]
        DelDB --> CheckDriverActive{Driver has other active trips?}
        CheckDriverActive -- No --> FreeDriver[(UPDATE employees SET status = 'available')]
        DelDB --> CheckVehicleActive{Vehicle has other active trips?}
        CheckVehicleActive -- No --> FreeVehicle[(UPDATE vehicles SET status = 'available')]
    end
```

## 8. Failure Modes, Resilience & Disaster Recovery

| Failure Scenario | Threat & Impact | Automated Mitigation & Architectural Redundancy |
| :--- | :--- | :--- |
| **Supabase GoTrue Outage** | Cloud auth unreachable; staff cannot login. | **Dual-Store Fallback**: Auth router automatically falls back to validating credentials directly against the local `users` table with bcrypt matching. |
| **Driver Drops Offline in Deadzone** | GPS telemetry stops; delivery status unconfirmed. | **Store-and-Forward**: Mobile app queues location pings and e-POD signature payloads in local SQLite/AsyncStorage; auto-retries upon signal re-establishment. |
| **Concurrent Dispatch Conflict** | Two dispatchers assign the same driver or vehicle. | **Atomic Status Guard**: SQL queries assert `WHERE status = 'available'`. If affected rows == 0, transaction aborts with HTTP 400 conflict error. |
| **Cloudflare Tunnel Failure** | Remote mobile drivers cannot hit Express API. | **Dynamic LAN Discovery**: Server binds to `0.0.0.0:3000` and displays local Wi-Fi LAN IP at startup (`http://192.168.x.x:3000`) for direct local network routing. |
| **Vehicle Breakdown Mid-Transit** | Shipment halted on highway. | **SOS Incident Protocol**: Driver hits red SOS panic button; system broadcasts `/api/notifications/alarm`; status page triggers siren; incident report logs coordinates for rescue dispatch. |
| **Email SMTP Server Timeout** | Milestone email delivery hangs. | **Asynchronous Fire-and-Forget**: Webhook dispatch is non-blocking (`Promise.catch` logged); trip status update returns immediately to caller without latency penalty. |

### Quick Startup Sequence:
1. Run `scripts/start_tunnel.bat` or `start_system.bat`.
2. The batch script spawns `cloudflared.exe tunnel --url http://localhost:3000`, establishes the encrypted tunnel, and displays the public `*.trycloudflare.com` URL.
3. The Express API initializes, verifies database connectivity to Supabase, binds to port `3000`, and exposes the static web client.
4. Electron launches the command desktop portal with context-isolated preload bridges.
5. Field drivers launch the Expo React Native app and point their API base URL to the secure Cloudflare tunnel.
